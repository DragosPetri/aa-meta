Interactive Config Workflow:
  1. requests all configs
  2. loop trough required configs asking for input (in case of default value, ask if default shall be used) and try to set config with given input
  3. display rest of configs asking if any shall be configured or left default/unset
  4. ask for input and configure for any optional config that is requested

NOTE: the underlying TOOL will either confirm a valid config is present or create the config file that will get populated with the required fields for the TOOL to work

NOTE: the underlying TOOL is permitted to do any pre/post init operations

NOTE: any 3rd party tool using attach-meta shall use init only to determine if a valid config is present or if there are still fields required to be populated

Autocompletion hook system:

On <TAB>: attach-meta __complete --current-word-index <N> -- <args>

NOTE: strips global flags before interpreting index
NOTE: index is 0 based
NOTE: index 0-1 is command/subcommand dispatch 

Meta side:
  1. Checks the tools supports __complete
  2. translates attach-meta protocol keywords to native tool keywords (e.g. delete === unset (zephyr))
  3. calls <binary> __complete --curent-word-index N -- <native_args>

Tool side:
  1. support __complete
  2. accept and parse <binary> __complete --current-word-index N -- <native_args>
  3. has it's own autocompletion analog_attachable
  4. outputs one candidate per line to stdout
  5. exit 0 (non-zero/empty stdout => no candidates)
